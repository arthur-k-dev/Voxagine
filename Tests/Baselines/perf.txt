# `work` metrics are exact and machine-independent: any increase is a
# regression and CI enforces them. `time` metrics only mean something
# against a recording from the same machine and build type, so they are
# reported rather than enforced unless --strict is passed.

# <system>/<benchmark>/<metric>  <value>  <kind>  [unit]
#
# Re-recorded 2026-08-09: VoxelBrickGrid::k_uiBrickShift went 3 -> 2, so a
# brick is 4^3 voxels rather than 8^3 and eight times as many of them cover
# the same volume. Exactly 8x, and set-writes/clear-writes did not move - the
# same voxels are written, the counter's unit shrank. Not a work regression.
#
# Re-recorded 2026-08-13 (chunk streaming phase 2). Three streaming changes,
# all deliberate: the 5x5 fixture gained a static VoxRenderer root per chunk
# (roots-per-entity-pass 6 -> 9), so that a chunk-restored renderer's re-stamp
# request - ledger M7 - is expressible at all; and the bounded unload added
# roots-per-unload-slice, encode-runs-per-slice, chunk-storage-reused/allocated
# and chunk-instance-restamps. The first two are the benchmark's own unit
# budgets, exactly, and are the assertion that a budgeted loop honours them.
#
# Re-recorded 2026-08-13 (chunk streaming phase 3). `roots-per-entity-pass` is
# gone rather than ratcheted: the uninterrupted pass it measured no longer
# exists. Loading a chunk's entities is two budgeted halves now and each has its
# own exact number - roots-per-staging-slice is the staging budget (2) and
# roots-per-admission-slice is what one static root per fixture chunk admits
# against a budget of 2. `gameplay-roots-per-admission` is the odd one out and
# the important one: it is deliberately unbounded and a *drop* in it is the
# regression, because every non-static root of the incoming window entering
# together is what makes a cross-chunk gameplay link impossible to observe
# half-made (ledger E3). The link counters are all zero on a fixture with no
# links; Tests/Streaming/EntityStreamingChecks.cpp carries those.
